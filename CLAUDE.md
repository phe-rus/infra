# CLAUDE.md

This is a Turborepo monorepo (bun workspaces: `["infra", "www", "plugins/*", "shared/*"]`).

- **`infra/`**: the actual auth server, the real `betterAuth()` engine (all plugins, D1/KV/R2), the admin dashboard, and only the admin-facing pages (`/setup`, admin `/sign-in`, `/forgot-password`). See `infra/CLAUDE.md` for its full architecture.
- **`www/`**: the end-user "my account" app (like myaccount.google.com). Runs no auth server of its own, purely a consumer of `infra` via `better-auth/react`'s `createAuthClient` (`www/src/lib/auth-client.ts`), pointed at `infra`'s URL. Hosts the OAuth provider's own pages (`/sign-in`, `/create-account`, `/two-factor`, `/consent`, `/forgot-password`, `/reset-password`) and the end-user's account surfaces under `_workspace`: a profile page, `/security` (2FA, passkeys, active sessions with per-device sign-out), and the wallets/payments section on the home page (saved mobile-money numbers, transaction history, a spend estimate, email receipts).

  **`www/src/functions/` is the data layer**, one file per read/write kind per domain, mirroring the split `infra/CLAUDE.md` documents for its own `kit/`: `get-<domain>.ts` holds every `createServerFn` for that domain first, then the `queryOptions`/`useSuspenseQuery` pairs built on them; `use-<domain>.ts` holds the `useAppMutation` hooks. `get-auth.ts` is the one exception worth knowing: `useLogout`, `useDeleteAccount`, `useRequestPasswordReset`, and `useResetPassword` all live there instead of in `use-auth.ts`, since none of them fit `useAppMutation`'s `invalidates`-a-query-key shape, they either swap the session identity entirely or end in an explicit navigate, so they call `useMutation` directly with their own toast/redirect logic, the same reasoning `infra/CLAUDE.md` documents for its own `kit/auth/use-*.ts` files. `use-auth.ts` only holds `useUpdateProfile`, the one auth-adjacent mutation that's a normal targeted-invalidate case. **A plain `authClient.*()` call inside a `queryFn` has no cookies to send during SSR** (`www`'s server has no browser cookie jar to draw from), which silently 500s a route's loader on a cold load, so every SSR-safe read wraps the `authClient` call in a `createServerFn()` handler that forwards `getRequestHeaders()` via `fetchOptions.headers`, the pattern `get-auth.ts`'s `currentUser` established first. Mutations skip this: they only ever fire from a browser after hydration, where `authClient` already carries real cookies. `www/src/features/<domain>/` holds the components a route composes, same shape as `infra/src/features/`; a route file itself stays down to just `Route` and `RouteComponent`, one loader `await` per query rather than a `Promise.all` (a single rejected `ensureQueryData` call shouldn't take the others down with it).
- **`shared/ui`** (`@infra/ui`): the one UI kit, consumed by both `infra` and `www`; neither app owns its own copy anymore. `src/components/*` (shadcn `aria-lyra` primitives, flat, no further nesting), `src/widgets/*` (`blocks/`: the `useAppForm` form system; `tables/`: `DataTable`; `dialog-widget/`: `DialogWidget`), `src/hooks/theme.tsx` and `src/hooks/defaults/*` (router loading/error/not-found fallbacks), `src/lib/utils.ts` (`cn`), `src/lib/use-media-query.ts`, and the global stylesheets (`globals.css`, `typeset.css`) all live here now: import via `@infra/ui/components/button`, `@infra/ui/widgets/tables`, `@infra/ui/widgets/blocks`, `@infra/ui/widgets/dialog-widget`, `@infra/ui/theme`, `@infra/ui/defaults`, `@infra/ui/lib/utils`, `@infra/ui/globals.css?url`, etc. (see its `package.json` `exports` map; this is a flatter layout than older docs describe; there is no `components/ui`/`components/widgets`/`components/defaults` nesting, and it isn't worth introducing just to match a stale description). The one exception: `infra/src/components/widgets/framework-icon.tsx` stays in `infra`: it's tied to `infra`'s own `kit/console` `Framework` type (the OAuth-client framework picker), so it's genuinely infra-specific, not reusable across apps.
- **`plugins/`**: `infra`'s two custom better-auth plugins, extracted out of `infra/src/auth/plugins/` so `www` (and any future third-party consumer) can call them too, not just `infra`'s own in-process `auth.api.*`:
  - **`plugins/r2`** (`@infra/r2`): object storage. Server plugin unchanged in behavior from before extraction, except `isAdminTier` is no longer imported directly; `r2Provider({ binding, isAdmin })` now takes an injected `isAdmin: (role) => boolean` callback (the caller's own role model, not assumed by the package, same principle as `binding` already being passed in rather than importing `env`). `@infra/r2/client`'s `r2Client()` gives `authClient.r2.*`: `list`/`delete` via plain better-auth path inference (`$InferServerPlugin` alone), `uploadAvatar(file, { userId? })`/`uploadFile(file)` as hand-written `getActions` that build the `FormData` a caller would otherwise have to construct by hand. `getCdnFile` (`/cdn/**:key`) has no client method at all: it's a public URL, built via the re-exported `cdnUrl()`, embedded directly (`<img src>`), never "called."
  - **`plugins/payment`** (`@infra/payment`, folder renamed from `infra-payment`, the "infra-" prefix was redundant once it's a `plugins/` package): PawaPay integration. `infraPayment({ apiToken, environment, cache, isAdmin, onPaymentCompleted? })`: `isAdmin` same as above; `onPaymentCompleted?: (email, receipt: PaymentReceiptInfo) => Promise<void>` replaces the old direct `sendPaymentReceiptEmail` import, called once when a payment first transitions to `completed` (optional, not every self-hoster wants receipt emails), and again on demand by `resendReceipt`. `@infra/payment/client`'s `paymentClient()` gives `authClient.pay.*` (`config`/`balances`/`deposit`/`payout`/`refund`) via plain inference: every endpoint is JSON in/out, no hand-written actions needed. `/pay/webhook` has no client method: PawaPay's servers call it directly, never a browser.

    Also self-service, all `sessionMiddleware`-gated: `myPayments` (`GET /pay/payments/mine`) is `www`'s only way to read a user's own payment history, since unlike `infra` it has no direct DB access, mirroring what `infra/src/kit/payments/fnc.ts`'s `listMyPayments` already does in-process. `resendReceipt` (`POST /pay/receipt/resend`) re-sends the receipt email for one of the caller's own completed payments on demand. A new `walletNumber` model (separate from `payment.phoneNumber`, which is per-transaction) backs a small set of saved-number endpoints: `listWalletNumbers`/`addWalletNumber`/`removeWalletNumber`/`setPrimaryWalletNumber` under `/pay/wallets*`. Every saved number starts `status: "pending"` and stays that way until a real deposit clears through that exact phoneNumber+provider pair, checked in `paymentWebhook` right after a payment flips to `completed`; that same check auto-promotes the newly verified number to primary if the user has none yet. `setPrimaryWalletNumber` rejects a still-pending number outright. `listWalletNumbers` sweeps pending numbers older than `WALLET_NUMBER_PENDING_TTL_MS` (24h) on every read rather than on a cron, since nothing in this project runs a scheduled worker yet; a number that's proven itself is never swept, verified or not.

  Both extractions surfaced the same infra-specific leak (`isAdminTier` imported directly rather than injected) that `binding`/`cache`/`apiToken` had already avoided, worth checking for the same pattern before adding a third plugin here.

`docs/` stays at the monorepo root, not inside `infra/`, since GitHub Pages serves it as a repo-root `/docs` folder, so nesting it under `infra/` would break the deployed docs site.

Root-level `package.json`/`turbo.json` orchestrate both apps' own scripts (`dev`/`build`/`typecheck`/`test`) via `turbo run <task>`; each app defines whichever of those it actually has. `lint`/`format`/`check` are root-only now (see below), not per-package turbo tasks. `.gitignore` and `.vscode/` live at root since they apply repo-wide, not just to `infra/`.

**Linting and formatting are one root-level `biome.json`**, replacing the old per-package ESLint (`eslint.config.js` + `@tanstack/eslint-config`) and Prettier (`.prettierrc`) setup entirely: `bun run lint`/`format`/`check` at the root call `biome lint`/`biome format --write`/`biome format` directly across the whole tree, no per-package scripts or turbo delegation needed since one Biome invocation from the root already covers every workspace. `indentWidth: 4`/`lineWidth: 100`/`quoteStyle: "double"`/`semicolons: "asNeeded"` match what the codebase actually looks like, carried over from the old Prettier config. `assist.actions.source.organizeImports` is explicitly off, same as the old config's `import/order`/`sort-imports` being disabled; imports are not auto-sorted here. A handful of `linter.rules` are turned off where Biome's recommended set conflicts with a deliberate pattern rather than catching a real bug: `noChildrenProp` (TanStack Form's own `<form.AppField children={(field) => ...}>` API), `useKeyWithClickEvents`/`noStaticElementInteractions`/`noSvgWithoutTitle` (a11y rules that don't fit this codebase's click-only interactive elements and decorative icons), `noArrayIndexKey`, `noNonNullAssertion`. `shared/ui/src/components/**` (shadcn-generated, never hand-edited) has linting disabled entirely via an `overrides` entry, same reasoning the old per-package eslint override there had. TypeScript is pinned to the `^7` line (the native-compiler rewrite) across every package now that nothing needs `typescript-eslint`'s TS-version compatibility window anymore.

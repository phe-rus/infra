# CLAUDE.md

This is a Turborepo monorepo (bun workspaces: `["infra", "accounts", "www", "plugins/*", "shared/*"]`).

- **`infra/`**: the actual auth server, the real `betterAuth()` engine (all plugins, D1/KV/R2), the admin dashboard, and only the admin-facing pages (`/setup`, admin `/sign-in`, `/forgot-password`). See `infra/CLAUDE.md` for its full architecture.
- **`accounts/`**: the end-user "my account" app (like myaccount.google.com), serving `account.pherus.org`. Runs no auth server of its own, purely a consumer of `infra` via `better-auth/react`'s `createAuthClient` (`accounts/lib/auth-client.ts`), pointed at `infra`'s URL. Hosts the OAuth provider's own pages (`/sign-in`, `/create-account`, `/two-factor`, `/consent`, `/forgot-password`, `/reset-password`) and the end-user's account surfaces under `_workspace`: a profile page and `/security` (2FA, passkeys, active sessions with per-device sign-out). No payments layer: `infra` is a pure auth/identity platform, so any app that needs payments wires its own. See `accounts/CLAUDE.md` for its full architecture — it mirrors `infra`'s own structure closely (flattened out of `src/`, the same `domains/<name>/{types,func,get-*,use-*,views,index}` shape, the same route-group guard conventions), a few intentional differences called out there (its mutation-hook calling convention, its non-throwing session middleware).
- **`www/`**: the public marketing site, serving the bare apex `pherus.org`. No auth or data layer by design (no `domains/`, no `QueryClient`), but real content: a landing page, `/blog` (posts sourced from `lib/config.ts`), `/faq`, and `/r/$slug` (one page per resource — Infra, Accounts, Seer, Transspace, etc. — also from `lib/config.ts`), plus a real `lib/seo.ts` (meta/OG/Twitter/canonical/JSON-LD) wired into every route's `head()`. See `www/CLAUDE.md`.
- **`shared/ui`** (`@infra/ui`): the one UI kit, consumed by every app (`infra`, `accounts`, `www`); no app owns its own copy anymore. `src/components/*` (shadcn `base-mira` primitives, built on Base UI (`@base-ui/react`) with HugeIcons (`@hugeicons/react` + `@hugeicons/core-free-icons`) — not react-aria-components/Tabler, which this codebase used previously — flat, no further nesting), `src/widgets/*` (`blocks/`: the `useAppForm` form system; `tables/`: `DataTable`; `dialog-widget/`: `DialogWidget`; `compose-viewport/`: the shared `<html>`/`<body>` shell every app's `__root.tsx` renders — `ComposeViewport.Window`'s `after` prop is where `<Scripts />` and `TanStackDevtools` must go, as direct `<body>` siblings rendered after `<main>`, never nested inside `<main>` as children; TanStack Router's own docs require `<Scripts />` near the end of `<body>`, and nesting it inside `<main>` previously caused a real hydration mismatch reproducible in all three apps, fixed once here rather than per-app), `src/hooks/theme.tsx` and `src/hooks/defaults/*` (router loading/error/not-found fallbacks), `src/lib/utils.ts` (`cn`), `src/lib/use-media-query.ts`, and the global stylesheets (`globals.css`, `typeset.css`) all live here now: import via `@infra/ui/components/button`, `@infra/ui/widgets/tables`, `@infra/ui/widgets/blocks`, `@infra/ui/widgets/dialog-widget`, `@infra/ui/theme`, `@infra/ui/defaults`, `@infra/ui/lib/utils`, `@infra/ui/globals.css?url`, etc. (see its `package.json` `exports` map; this is a flatter layout than older docs describe; there is no `components/ui`/`components/widgets`/`components/defaults` nesting, and it isn't worth introducing just to match a stale description). The one exception: `infra/domains/console/views/framework-icon.tsx` stays in `infra`: it's tied to `infra`'s own console `Framework` type (the OAuth-client framework picker), so it's genuinely infra-specific, not reusable across apps.
- **`plugins/`**: `infra`'s custom better-auth plugins, extracted out of `infra/src/auth/plugins/` so other apps (and any future third-party consumer) can call them too, not just `infra`'s own in-process `auth.api.*`:
  - **`plugins/assets`** (`@infra/assets`, package renamed from `@infra/r2`/`plugins/resources`): object storage. Exported as `assets({ binding, isAdmin })`, taking an injected `isAdmin: (role) => boolean` callback (the caller's own role model, not assumed by the package, same principle as `binding` already being passed in rather than importing `env`) — registered in `infra/auth/auth.ts`'s `plugins` array, mounting its endpoints under `/api/auth/assets/*`. `@infra/assets/client`'s `assetsClient()` gives `authClient.assets.*`: `list`/`delete` via plain better-auth path inference (`$InferServerPlugin` alone), `uploadAvatar(file, { userId? })`/`uploadFile(file)` as hand-written `getActions` that build the `FormData` a caller would otherwise have to construct by hand. The public CDN read path (`/api/cdn/**`) is deliberately a separate, plain, non-auth route (`infra/src/routes/api/cdn/$.ts`), not one of this plugin's endpoints — see `infra/CLAUDE.md` for why.

  No payments plugin here by design: `infra` is a pure auth/identity platform (the same split as Firebase Auth vs. Firebase's own billing), so an app that needs payments wires its own integration rather than `infra` shipping a shared one. A `plugins/payprovider` (PawaPay) and `plugins/notify` package existed for a while but were removed entirely — don't reintroduce either without that decision being revisited.

Root-level `package.json`/`turbo.json` orchestrate every app's own scripts (`dev`/`build`/`typecheck`/`test`) via `turbo run <task>`; each app defines whichever of those it actually has. `lint`/`format`/`check` are root-only now (see below), not per-package turbo tasks. `.gitignore` and `.vscode/` live at root since they apply repo-wide, not just to `infra/`.

**Linting and formatting are one root-level `biome.json`**, replacing the old per-package ESLint (`eslint.config.js` + `@tanstack/eslint-config`) and Prettier (`.prettierrc`) setup entirely: `bun run lint`/`format`/`check` at the root call `biome lint`/`biome format --write`/`biome format` directly across the whole tree, no per-package scripts or turbo delegation needed since one Biome invocation from the root already covers every workspace. `indentWidth: 4`/`lineWidth: 100`/`quoteStyle: "double"`/`semicolons: "asNeeded"` match what the codebase actually looks like, carried over from the old Prettier config. `assist.actions.source.organizeImports` is explicitly off, same as the old config's `import/order`/`sort-imports` being disabled; imports are not auto-sorted here. A handful of `linter.rules` are turned off where Biome's recommended set conflicts with a deliberate pattern rather than catching a real bug: `noChildrenProp` (TanStack Form's own `<form.AppField children={(field) => ...}>` API), `useKeyWithClickEvents`/`noStaticElementInteractions`/`noSvgWithoutTitle` (a11y rules that don't fit this codebase's click-only interactive elements and decorative icons), `noArrayIndexKey`, `noNonNullAssertion`. `shared/ui/src/components/**` (shadcn-generated, never hand-edited) has linting disabled entirely via an `overrides` entry, same reasoning the old per-package eslint override there had. TypeScript is pinned to the `^7` line (the native-compiler rewrite) across every package now that nothing needs `typescript-eslint`'s TS-version compatibility window anymore.

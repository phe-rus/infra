# CLAUDE.md

This is a Turborepo monorepo (bun workspaces: `["infra", "www", "plugins/*", "shared/*"]`).

- **`infra/`** — the actual auth server: the real `betterAuth()` engine (all plugins, D1/KV/R2), the admin dashboard, and only the admin/owner-facing pages (`/setup`, admin `/sign-in`, `/forgot-password`). See `infra/CLAUDE.md` for its full architecture.
- **`www/`** — the end-user "my account" app (like myaccount.google.com). Runs no auth server of its own — purely a consumer of `infra` via `better-auth/react`'s `createAuthClient` (`www/src/lib/auth-client.ts`), pointed at `infra`'s URL. This is also where `/sign-in`, `/create-account`, `/consent` (the OAuth provider's hosted pages) and payments UI are meant to live once built — currently a blank TanStack Start scaffold aside from a smoke-test use of `@infra/ui`.
- **`shared/ui`** (`@infra/ui`) — the one UI kit, consumed by both `infra` and `www`; neither app owns its own copy anymore. `components/ui/*` (shadcn `aria-lyra` primitives), `components/widgets/*` (`useAppForm`/blocks form system, `DataTable`, `DialogWidget`), `components/defaults/*` (router loading/error/not-found fallbacks), `lib/utils.ts` (`cn`), `lib/use-media-query.ts`, and the global stylesheets (`globals.css`, `typeset.css`) all live here now — import via `@infra/ui/components/ui/button`, `@infra/ui/lib/utils`, `@infra/ui/globals.css?url`, etc. (see its `package.json` `exports` map). The one exception: `infra/src/components/widgets/framework-icon.tsx` stays in `infra` — it's tied to `infra`'s own `kit/console` `Framework` type (the OAuth-client framework picker), so it's genuinely infra-specific, not reusable across apps.
- **`plugins/`** — `infra`'s two custom better-auth plugins, extracted out of `infra/src/auth/plugins/` so `www` (and any future third-party consumer) can call them too, not just `infra`'s own in-process `auth.api.*`:
  - **`plugins/r2`** (`@infra/r2`) — object storage. Server plugin unchanged in behavior from before extraction, except `isAdminTier` is no longer imported directly; `r2Provider({ binding, isAdmin })` now takes an injected `isAdmin: (role) => boolean` callback (the caller's own role model, not assumed by the package — same principle as `binding` already being passed in rather than importing `env`). `@infra/r2/client`'s `r2Client()` gives `authClient.r2.*`: `list`/`delete` via plain better-auth path inference (`$InferServerPlugin` alone), `uploadAvatar(file, { userId? })`/`uploadFile(file)` as hand-written `getActions` that build the `FormData` a caller would otherwise have to construct by hand. `getCdnFile` (`/cdn/**:key`) has no client method at all — it's a public URL, built via the re-exported `cdnUrl()`, embedded directly (`<img src>`), never "called."
  - **`plugins/payment`** (`@infra/payment`, folder renamed from `infra-payment` — the "infra-" prefix was redundant once it's a `plugins/` package) — PawaPay integration. `infraPayment({ apiToken, environment, cache, isAdmin, onPaymentCompleted? })` — `isAdmin` same as above; `onPaymentCompleted?: (email, receipt: PaymentReceiptInfo) => Promise<void>` replaces the old direct `sendPaymentReceiptEmail` import, called once when a payment first transitions to `completed` (optional — not every self-hoster wants receipt emails). `@infra/payment/client`'s `paymentClient()` gives `authClient.pay.*` (`config`/`balances`/`deposit`/`payout`/`refund`) via plain inference — every endpoint is JSON in/out, no hand-written actions needed. `/pay/webhook` has no client method — PawaPay's servers call it directly, never a browser.

  Both extractions surfaced the same infra-specific leak (`isAdminTier` imported directly rather than injected) that `binding`/`cache`/`apiToken` had already avoided — worth checking for the same pattern before adding a third plugin here.

`docs/` stays at the monorepo root, not inside `infra/` — GitHub Pages serves it as a repo-root `/docs` folder, so nesting it under `infra/` would break the deployed docs site.

Root-level `package.json`/`turbo.json` orchestrate both apps' own scripts (`dev`/`build`/`lint`/`typecheck`/`test`/`format`/`check`) via `turbo run <task>` — each app defines whichever of those it actually has. `.gitignore` and `.vscode/` live at root since they apply repo-wide, not just to `infra/`.

# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`www` is the public marketing site for Pherus, serving the bare apex `pherus.org`: still no auth, no data fetching, no `domains/`, no `QueryClient` — every page is static and English-only. `accounts` (`account.pherus.org`) and `infra` (`infra.pherus.org`) carry the actual product. See the monorepo root `CLAUDE.md` for the `infra`/`accounts`/`www` split.

All real routes live under a `/_workspace` layout route (`src/routes/_workspace/route.tsx`), which wraps every page in shared `<Headers />`/`<Footers />` chrome (`components/headers/`, `components/footers/`, both top-level dirs — not under `src/`). There is no `src/content/`, `src/data/divisions.tsx`, `division-mark.tsx`, or `@tanstack/markdown` dependency anymore; the earlier About-page/division-grid approach described here previously was superseded by the current landing-page layout below. All page content (division lists, blog posts, etc.) is plain inline TypeScript data inside the route file that uses it — no markdown files, no shared `content/`/`data/` module. Route components define nothing at module scope except the `Route` export itself; any local data goes inside the route's own component function, via `useMemo` when it's more than trivial.

This app shares `@infra/ui`'s actual design tokens and components (`Button`, `Badge`, `Avatar`, `buttonVariants`, etc.) — it does not carry its own color palette or font stack. Icons come from HugeIcons (`@hugeicons/react`'s `HugeiconsIcon` + `@hugeicons/core-free-icons`), not Tabler, which this codebase used previously — every icon usage is `<HugeiconsIcon icon={SomeNameIcon} />`, never a bare `<IconSomeName />`. A link styled as a button uses TanStack Router's own `<Link>` with `buttonVariants({ variant, size })` applied as `className`, not `LinkButton` (that renders a plain `<a>`, losing TanStack Router's client-side navigation). `<Button render={...}>` is fine to use directly if needed: `@infra/ui`'s components are now built on Base UI (`@base-ui/react`), whose `render` prop accepts a bare `ReactElement` (not react-aria-components' render-function shape this codebase used previously). `motion` (the `framer-motion` successor) is used for the header's mega-menu enter/exit (`AnimatePresence`) — the only animation lib in the app.

**Routes**: `/` (`_workspace/index.tsx`) is the real, actively-worked landing page — hero, a "what we're working on" chip grid of every Pherus division, a testimonials rail, and a community-links grid. Its copy is placeholder/mockup content, not final: testimonial text and video are stock filler unrelated to Pherus (Blue Origin/Payload quote, a Google marketing-CMS demo video), and one heading has a typo ("herus"). Don't treat this page's text as approved copy to reuse elsewhere. `/blog`, `/faq`, and `/r/$slug` (a generic resource/detail page — the header's Resources mega-menu links here, e.g. `/r/infra`, `/r/accounts`) are stub pages: a bare `ViewController` (from `@infra/ui/widgets/view-controller`) with a "Hello" heading and repeated lorem-ipsum paragraphs, not yet built out.

**Header** (`components/headers/`): `config.ts` defines a `NavItem[]` tree — flat `NavLink`s (`Overview`, `FAQ`, `Blog`) alongside `NavGroup`s (`Resources`, containing nested `NavSection`s that render as `views/mega-menu.tsx` on hover, e.g. "Platforms & Services" / "Organizations"). `views/mobile-nav.tsx` covers the same tree with swipe support below `md`; `views/nav-trigger.tsx` is the shared trigger button for both flat links and group headers.

**Footer** (`components/footers/`): `config.ts` is currently generic placeholder IA — categories like "Products" (Product A-E), "Industries", "Solutions", and links to routes that don't exist yet (`/login`, `/signup`, `/docs`, `/pricing`, `/about/*`). Treat it as a layout/columns mockup, not a real sitemap to link elsewhere or extend.

Package manager: **bun** (`bun.lock` is the lockfile, gitignored, autogenerated by `bun install`, never committed).

## Commands

```bash
bun install       # install dependencies
bun run dev       # start dev server on port 3002
bun run build     # production build
bun run typecheck # tsc --noEmit
bun run deploy    # wrangler deploy
```

## Architecture

Same 4-file TanStack Start convention as `infra`/`accounts` (`src/start.ts`, `src/server.ts`, `src/router.tsx`, `src/routes/__root.tsx`), stripped of everything session/query-client related since this app has no state to bootstrap. Everything else lives under the `/_workspace` layout route described above, not directly in `src/routes/`.

Don't add `better-auth`, `@tanstack/react-query`, or a `domains/` folder here — if a feature needs any of those, it belongs in `accounts`, not `www`.
